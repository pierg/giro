# Prompts and skills live apart cleanly

Supersedes [ADR-0011](0011-host-skills-and-engine-prompts-live-apart.md). ADR-0011 conflated three touchpoint kinds under one `skills/` directory and gave them all the SKILL.md format; its follow-up split them across three dirs (`skills/`, `prompts/`, `gates/`) but kept SKILL.md for everything, which meant engine prompts had YAML frontmatter the resolver had to strip and gate criteria kept a `type = "skill"` foothold that let a project's `skills/<name>/SKILL.md` shadow a bundled criterion. Decided: everything the engine injects lives in `prompts/` as **plain markdown** (`worker.md`, `planner.md`, `review.md`, `conformance.md` — no frontmatter, nothing to strip); operator skills stay in `skills/` as host-discoverable SKILL.md files, giro-prefixed (`giro`, `giro-setup`, `giro-spec`, `giro-plan`, `giro-grill`); gate types collapse to `command | judge`, where a judge references a criterion by name (resolving to `prompts/<name>.md`) or carries an inline `rubric`; and the roster role `implementer` is renamed `worker` to match the vocabulary (the legacy name is accepted with a deprecation notice for one cycle).
