# GitHub is a one-way, fail-soft projection

giro's state should be visible where humans already look — GitHub issues, pull requests, phone notifications — but control must not cross an LLM, and it must not cross a webhook either. Decided: GitHub is a projection of the markdown store — the engine renders state outward (tracking issue, sub-issues, labels, comments, draft-to-ready pull request, commit statuses) via `gh` from its main thread only, records the GitHub identifiers in frontmatter, and never reads GitHub back into control flow; `giro project` reconverges the surface from markdown at any time.

Consequences: a deliberate inversion of ADR-0006 at the boundary — gates fail closed, projection fails soft at runtime, because a dead network may cost visibility but never work. Preflight is the exception: when `[github_projection] enabled = true`, a failing preflight (missing `gh`, invalid token, unreachable repository, uncreatable labels) refuses the Run rather than running it silently blind — the operator asked for the surface, so "silently off" would be the wrong answer, and `giro project --check` proves the same conditions before dispatch. Pushes happen only at post-decision checkpoints, so published history only grows and the engine never force-pushes.
