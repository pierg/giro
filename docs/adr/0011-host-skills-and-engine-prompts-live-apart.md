# Host skills and engine prompts live in separate directories

Superseded by [ADR-0015](0015-prompts-and-skills-live-apart-cleanly.md).

Refines [ADR-0002](0002-cli-owns-the-loop-skills-are-touchpoints.md). "Skills are the touchpoints" is right, but three kinds of touchpoint were conflated in one `skills/` directory and all copied into host discovery by `giro install`, which surfaced engine internals (`implement`, `review`, `conformance`) as chat-invokable commands — a category error, since invoking them without the engine's packet or verdict envelope is meaningless or actively the bypass the doorway forbids. They now live apart by consumer: `skills/` holds **host skills** a person invokes (`giro`, `spec`, `plan`, `grill`) and is the *only* thing `giro install` places into `.claude/skills/`; `prompts/` holds **engine prompts** the engine splices into a worker (`implement`); `gates/` holds **gate criteria** a judge applies (`review`, `conformance`, or your own, referenced by a `type = "skill"` gate). All three keep one editable SKILL.md format and one project-override chain; only host skills have a `.claude/skills` leg, because the engine must never resolve its internals from host-discovery territory.
